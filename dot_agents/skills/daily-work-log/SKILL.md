# 每日工作日志

把当天工作事实整理为简洁、可核查、能体现技术价值的中文日报。评分口径用于补齐证据和改善表达，不是夸大贡献的许可。

## 工作流

1. 读取 [references/project-profile.md](references/project-profile.md)，按 Asia/Shanghai 确定目标日期，并获取 Notion 当前结构。
2. 汇总目标日的 Notion 原始记录、用户在聊天中提供的事实，以及当天本人的 Git 提交。Git 仅作补充证据；必要时只读查看差异。
3. 读取最近 5 个工作日的历史日报。若当天事项涉及版本、推进中任务或承诺节点，继续追溯到最近一次明确状态，然后停止。
4. 为每项事实识别：本人角色、当天增量、项目与模块、目的或问题、真实难点、具体改动、影响范围、验证结果、数量、当前状态和下一节点。合并同一成果的重复记录。
5. 核对历史重复、版本范围、状态衔接、进度口径、承诺节点和事实支持的交付风险。先完成有依据的草稿，再集中提出会改变归属、状态或价值判断的关键问题。
6. 按“价值链”写作规则生成日报，并用 [references/scoring.md](references/scoring.md) 做一次内部诊断。除非用户要求，不在最终日报中显示分数。
7. 按 [references/notion.md](references/notion.md) 保存或更新待确认稿，随后在聊天中展示完整日报、待核实项和 Notion 页面链接。

资料不足时仍完成有依据的部分。无法访问来源或保存失败时，如实说明缺失范围；不以追问替代已经能够完成的工作。

## 证据与状态

- 只写有依据的本人贡献；其他作者、历史成果和其他日期的结果不计为当天新增。
- 区分开发完成、待验证、验证通过、部署、上线、验收和交付，一个状态不替代另一个。
- “主动发现”“牵头”“协调”“支持”等角色必须有事实支持；被动任务按实际角色表述。
- 进度、数量、收益和影响人数采用原始记录或可核查证据；未统计时保留定性描述。
- 区分项目整体进度与版本进度。范围变化导致口径变化时说明原因，不沿用历史百分比。
- 发现矛盾、缺失或明显风险时，在聊天中另列简短的“需核实/风险”，注明对应日期和事实；在 Notion 待确认稿中记录待核实项，不把推测写成事实。没有实质问题时不制造风险。

## 价值链表达

每条优先形成以下逻辑，而不是机械套句式：

> 为实现某项功能或解决某个问题，针对有依据的挑战或难点，完成或调整具体架构、模块、接口、页面、工程化或测试工作，说明影响范围，并用验证结果或数量体现价值。

写作时遵循：

- **目的**：说明实现了什么功能，或解决了什么业务、技术、交付问题。
- **难点**：只写真实存在的复杂度，如架构边界、权限模型、跨端契约、数据迁移、模型调用、兼容性、性能或跨系统联调。
- **改动**：落到架构、业务模块、接口、页面、工程化流程或测试体系，不停留在“处理、跟进、优化”等活动词。
- **影响**：指出受影响的模块、接口、页面、环境、版本或交付环节。
- **验证与量化**：优先使用模块数、接口数、页面数、功能点数、问题数、测试数、服务器数、版本数和分支数；没有可靠数量时使用明确的定性结果。

每条不必同时出现五个部分，但至少写清“目的或问题 + 具体改动 + 结果或影响”。挑战、价值和数字均须有证据。

## 合并与格式

- 所有成果按业务大模块合并，每个模块原则上一条；接口、页面和数量写入对应模块。
- 每条“已完成”和“推进中”都以 `【项目名｜模块名】` 开头。当前项目按项目配置使用统一名称。
- 日报不展示代码行数、文件路径、文件清单或提交哈希；除非用户明确要求，也不以代码增删行数或文件数作为主要量化指标。
- “已完成”只写当天已经达到明确完成状态的成果；“推进中”写当天增量、当前状态、阻塞或下一节点，没有内容的小节省略。

```text
王伟 - 工作记录 (YYYY-MM-DD)：

已完成：
- 【项目名｜模块名】目的或问题、具体改动、影响范围及可验证结果

推进中：
- 【项目名｜模块名】当天增量、当前状态、阻塞或下一节点
```

默认自然、务实、简洁。最终正文只保留日报；评分诊断、提升问题和待核实项放在正文之后。

## 交互与权限

- 定时提醒每天只生成并保存一次待确认稿。用户补充事实后，更新同一天的同一份日报。
- 用户确认后将该稿标记为已确认；确认本身不授权向 Hermes、飞书或其他人发送。
- 只有用户明确要求外发当前日期、当前版本时，才读取并执行 [references/external-submit.md](references/external-submit.md)。
- 用户要求“记工作”时，将原始事实写入 Notion 原始工作记录，而不是日报记录；仅写用户明确给出的日期、项目、结果、问题和下一步，写入后返回记录链接。
