# 日志价值诊断

评分只诊断材料完整度，不冒充领导最终评分，也不默认写入日报正文。

| 维度 | 权重 | 核查重点 |
| --- | ---: | --- |
| 交付产出量与密度 | 30 | 独立成果、覆盖模块、接口、页面或功能点 |
| 技术复杂度 | 20 | 架构、权限、契约、迁移、兼容、性能、模型或跨系统联调 |
| 可验证成果 | 20 | 测试、验证、部署、上线、验收及有依据的效果指标 |
| 主动性与协作 | 15 | 有证据的风险识别、决策推动、资源协调、现场或评审支持 |
| 计划闭环度 | 10 | 承诺节点、推进项收口、阻塞和下一节点 |
| 日志可核查性 | 5 | 项目、日期、模块、状态、数量和来源是否可对应 |

## 诊断方式

1. 将每项事实映射到相关维度，检查是否存在重复、冲突、跨日期挪用或状态越级。
2. 先输出一版可用日报，再按预计价值从高到低集中提出用户能够回答的问题。
3. 优先询问会改变成果价值的缺口：目的、实际难点、本人角色、影响范围、验证结果、数量和承诺节点。
4. 用户补充后重写完整日报；无法补充时保留证据版，不为提高分数编造内容。

用户要求查看诊断时，在日报正文后提供简短的各维度证据、主要缺口和非官方估分。用户确认最终稿后，只保留完整日报和必要的待核实项。
